1 · The one-line verdict

Structurally a RAG system, built with Agentic RAG in mind — but today it runs as a fixed pipeline, not a reasoning agent.

agent-core is a genuine RAG system with an extra write-back loop that lets it learn across sessions. What it is not yet is Agentic in the technical sense: the LLM never decides whether or what to retrieve, never reformulates a query, never loops or reflects, and never calls a tool. Those “decisions” are made by deterministic keyword rules and a strictly linear LangGraph. The foundation is right; the agentic behaviours are still TODOs.

2 · Where it is RAG ✓

The classic retrieve → augment → generate cycle is fully present — plus a learning loop most vanilla RAG lacks.

RAG stageIn agent-core
Retrievememory_retriever_node → get_relevant_memories() → search_memory() against ChromaDB, across 4 collections, scoped by user_id + agent_id
Augmentcontext_builder_node + prompt_builder_node inject retrieved memories into a sectioned prompt ([USER MEMORY], [CONVERSATION MEMORY], …)
Generatellm_node calls the model with that augmented prompt via the LLM router
Write-back (bonus)writeback_node summarizes, extracts facts, and stores new memories — closing a read → answer → learn loop
user message → RETRIEVE memories → AUGMENT prompt → GENERATE reply → WRITE-BACK new memories → (next turn remembers)

That closed loop is what turns a stateless LLM into a companion with continuity — the core product promise, and unambiguously RAG.

3 · What “agentic” adds — and what’s missing

“Agentic RAG” = the agent/LLM dynamically drives retrieval and reasoning, instead of following a fixed script.

In Agentic RAG the model itself decides whether to retrieve, what to search for, reformulates queries, grades and re-ranks results, loops when the answer isn’t good enough, and chooses tools. Measured against that bar, here’s the current state:

Present

  • A multi-stage LangGraph pipeline over a shared state
  • Memory retrieval + write-back loop
  • An understanding layer (intent, emotion)
  • A provider router with automatic fallback
  • A deterministic safety gatekeeper

Missing (the “agentic” part)

  • No dynamic decision to retrieve — always top-5 from all stores
  • No query reformulation / re-ranking / relevance grading
  • No loops or conditional edges — the graph is strictly linear
  • No LLM-driven routing — decisions are keyword rules
  • No tool use / function calling
  • No self-reflection on its own answer
The key nuance The “agentic” behaviours the vision describes (when to comfort, ask a follow-up, motivate) are expressed through the prompt and persona — not through actual agent control flow. LangGraph is used, but only as a linear state machine; none of its branching/looping (the thing that makes a graph agentic) is used.

The retrieval caveat matters most Because embeddings are a deterministic hash stub, “similarity” today behaves closer to fuzzy text-identity than true semantic meaning. Even the “R” in RAG isn’t fully realized until a real embedding model is dropped in — the interface for that already exists.

6 · The path to true Agentic RAG

Ordered by impact-per-effort. None of these require throwing away what exists.

#ChangeWhy it matters
1Real embeddings — swap the hash stub for an actual model (interface already exists)Without it, RAG retrieval isn’t semantically meaningful. Highest priority.
2Conditional graph edges — e.g. crisis fast-path skips the LLM; skip retrieval on trivial turnsSmallest change that makes the graph genuinely branch. Also improves safety & cost. LangGraph add_conditional_edges.
3Agent-driven retrieval — LLM decides what/whether to retrieve and reformulates the queryThe core of “agentic” retrieval vs. a fixed top-5.
4Retrieval grading + loop — grade memory relevance, optionally re-retrieve (a cycle)Turns the pipeline into an iterative agent.
5LLM-based (or hybrid) classification instead of pure keyword rulesAdaptive intent/emotion handling.
6Tool calling — reminders, activity suggestions, etc. as real toolsLets the agent act, not just talk.
Recommended first step Item 2 (a conditional crisis fast-path that bypasses the LLM entirely) is the cheapest move that meaningfully increases “agentic-ness” — and it hardens safety at the same time, since a crisis reply would no longer depend on the model behaving.

7 · Bottom line

  • RAG: yes — structurally complete; quality gated on real embeddings.
  • Agentic: not yet in the technical sense — a fixed, linear pipeline rather than an agent reasoning about its own retrieval and steps.
  • Alignment with the stated “Agentic RAG” vision: on track — the scaffolding (LangGraph, memory service, write-back, safety, provider routing) was clearly built with Agentic RAG in mind. It’s a strong foundation; the defining agentic behaviours are the remaining work.

In short: call it “RAG with an agentic-ready architecture.” The distance to genuine Agentic RAG is a handful of additive changes — chiefly real embeddings and conditional/looping edges — not a redesign.
